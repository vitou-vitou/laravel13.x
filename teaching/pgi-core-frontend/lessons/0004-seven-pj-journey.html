One Arc, Every Product

L1 QUOTE              L2 POLICY               L3 ENDORSEMENT
price it              bind it                 change it mid-term
     │                     │                        │
     └── customer accepts ─┘                        └── (repeat)

Product code only swaps which fields show. Path never changes. That is why you can lead quality without knowing every insurance clause.

What Each Level Means (Plain English)

Level Staff action Customer sees Must work
L1 Quote Create / edit Info + Plan, save, print Price offer PDF Hydrate + save + PDF not blank
L2 Policy Issue from quote, edit Premium, print Bound contract PDF Convert + save + policy PDF
L3 Endorsement Generate mid-term change, save, print Change document PDF Generate + save + endt PDF
CEO Translation

"Every live product supports quote, bind, and mid-term change — with printable PDFs at each step. That is the insurance operating loop our underwriters run."

WIP Rule (Don't Get Caught)

WIP lines (0201, 0202) sit on the same 7pj path, but:

  • OK: list / view / edit existing records + PDF
  • Not OK: new quote create until sale: live

If someone demos a WIP create-quote and it fails — that is expected, not a production outage.

How You Count "Done"

One product × 3 levels = 3 cells. A cell is done only when:

  1. Save works (no surprise error toast)
  2. Detail view shows data
  3. PDF prints with real content (not empty schedule)

Rough math for live: 11 journeys × 3 = 33 live cells. WIP adds 6 cells for existing-record ops only.

Your Job as Lead (Not UW)

  • Ask: "Which cell failed — L1, L2, or L3?"
  • Ask: "Save, view, or PDF?"
  • Do not dig into clause wording first — triage the cell
